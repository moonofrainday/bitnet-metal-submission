# 已选 Qcur-0 kernel 的 Mac 价值验证

本轮只验证已经选定的 Q4（stock4x1），没有重新挑选 kernel，也没有修改点积算法。结论是：**单算子有可重复收益，当前第 0 层接入没有带来整模型加速。** 这支持它作为范围明确的单层 PoC，尚不能证明它是模型里最值得优先优化的瓶颈。

## 条件与正确性

- 设备：MacBook Pro M2 Pro，16 GB；macOS 27.2.1，Xcode 27.2，SDK 27.2。
- 公开 2B TQ2_0 模型；ActQuant ON、F16 KV；原 27-token prompt 和两组固定 32-token history。
- S 为实际 stock；QB 完整执行候选守卫和库查询后，仍使用同一个 stock pipeline、ABI、buffer 绑定与 launch；Q4 为保留 stock helper 四行算术的 4×1 特化。
- Q4 只接管第 0 层 `Qcur-0` 单 token decode。每条回放目标命中 32 次，模型所有层 Q 身份共 960 次；其余节点及 prefill 保持 stock。
- 已有同构建双 history 门槛复用并核对哈希：全部 32 次 Q、steps 1/16/32 层输出、33 份 logits 的局部验收通过。
- 新独立算子检查覆盖 steps 1/16/32、S/Q4 两路，共 15,360 个输出；原 FP64 容差失败 0、非有限值 0、stock 逐位差异 0，输入和边界 canary 未改变。

原容差仍为 `abs(error) <= 2e-4 + 2e-5 * abs(reference)`。Q4 是 stock helper 特化，不是原创 4×2 PoC 或 C8×2；这些实现的证据不能相互代替。完整可信模型参考的历史严格比较仍为退出码 1，本轮没有修复或改判模型语义／质量。

## 单算子性能：收益成立

固定真实 step-16 W/X；每路预热 30 次，每轮交替 201 对，共 3 轮。每个 command buffer 只有一次 dispatch，完成后读取 `GPUEndTime-GPUStartTime`，单位 µs。计时关闭 capture、读回与诊断；不包含 guard、ActQuant 准备或模型调度。

## 整模型：没有测到加速

同进程、同模型/context，每条路径先清理 KV 并恢复相同前缀；恢复在计时外。每路预热两次完整回放，3 轮×21 对，平衡 AB/BA 并轮换对照组顺序。正式计时关闭诊断和读回，保留原每 token 同步。

## Guard 归因：定位到部分 CPU 成本

QB 确实完成完整检查后再执行 stock，未通过提前 fallback 冒充对照。原 prompt 的 32 次 QB 守卫累计约 1.194 ms，其中 getter 约 1.135 ms、文件身份 snapshot/key 约 1.109 ms。32 次查询全为 warm cache hit，miss/load 为 0；本次样本不支持“每次重新编译 shader”的解释。

这些是包含抢占／等待的主机 elapsed 区间，且多层嵌套，不能简单相加。独立 prompt 的一条 QB 诊断还出现更广泛编码区间变慢。因此，只能确认身份检查／缓存键是本次观察到的重要主机成本，不能声称它解释了全部 decode 墙钟差值，更不能据此重新归因旧手机对照的约 10～13 ms。

## 真实图 GPU 时间戳与边界

在另一 worktree 中加入可选探针：不改变 shader，在同一个原 command buffer 内切分 encoder、加入 fence 和 stage-boundary timestamp。两组 history 的局部数值验证通过；原 prompt OFF/ON 保存的 199 份 payload 逐位一致。普通诊断四条目标路径各有 32 个有效区间，p50 为 24.459～24.792 µs；空 encoder 对照 p50 为 0.500～0.541 µs，单独保留。

探针会改变调度。三轮 metrics-only 的附加墙钟约 1.392～1.707 ms，metrics＋切分探针约 2.738～3.048 ms；两次 campaign 不可相减来宣称纯 encoder 成本。目标区间不是正常关键路径占比，空区间也不能直接扣掉当作纯 kernel 时间。

正常 Instruments 两次启动都未形成原生推理结果；首次有 AMFI 签名诊断，复制并重新开发签名后仍失败，第二次原因未解决。**正常关键路径份额仍为 null**。ALU、带宽、occupancy、寄存器压力和 stall counters 没有取得，不能用它们解释本次加速。

## 如何回答“值得优化吗”

模型确有 210 个 TQ2_0 投影权重、30 个 Q 权重，其中 60 个为 2560×2560；这是结构复用机会，不是耗时占比，也不是这些位置全部通过接入验收。

当前只替换一层一个投影。条件性预算：**假设**独立测得的每次约 1.958 µs 节省能原样进入图中且没有新增开销／重叠变化，32 步合计约 62.7 µs，仅相当于 432 ms 回放的约 0.0145%。这不是实际端到端收益、预测或保证上界，不能再乘 60/210。

因此保留 stock 默认路径，Q4 保留为正确的局部优化 PoC。晚上优先用已准备的相同 S/QB/Q4 对照在 A16 复核；Mac 的 8.3% 不写成手机结果。后续最小实现问题是能否把不可变 session 计划移出热路径，同时保留换库、错配几何和缓存失效的安全检查；本轮尚未实现或测量该修复。
